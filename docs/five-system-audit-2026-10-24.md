## 已修正：介面選的日期與引擎實際排的日期不同

| 操作／輸入 | V14 可重現結果 | V15 |
|---|---|---|
| 任一系統，選 2026-01-31，再把月份改為 02 | `day` 仍為 31，選單已無該選項；引擎把 2026-02-31 正規化成 2026-03-03，與標示月份不同 | 年／月改變時，同步把日期縮至該月最後一天：2026-02-28 |
| 任一系統，2028-02-29 改年為 2029 | 仍持有不存在的 2029-02-29；引擎實際排 2029-03-01 | 2029-02-28 |
| 月家 2026-01-31 13:30，按下一月 | 本地 `Date.setMonth()` 溢位到 2026-03-03，跳過二月 | 2026-02-28 13:30 |
| 月家 2028-03-31 13:30，按上一月 | 溢位成 2028-03-02，仍停在三月 | 2028-02-29 13:30 |
| 年家 2028-02-29 13:30，按下一年 | 2029-03-01 | 2029-02-28 13:30 |
| 宿主 `America/Los_Angeles`，2026-03-08 01:30 按下一時（+2 小時） | 本地夏令時間跳躍，變成 04:30；台灣／UTC 卻為 03:30 | 各宿主均為輸入民用時間 03:30 |
| 1901-01-01 按上一日，或 2100-12-31 按下一月 | 可產生年份選單以外日期 | 超出 1901–2100 的導覽按鈕停用 |
| UTC 時刻 2026-10-23T16:00:00Z，按現在時間 | 依裝置時區填入，與引擎「台灣民用日期」的約定不一致 | 明示「台灣現在時間」，填入 2026-10-24 00:00 |

根因位於 `src/App.jsx` 的年／月選單與 `qc()`，不是九星、八門或十二長生公式。新模組 `civil-date.js` 統一執行日數縮限與純日曆導覽；月／年導覽先移至一日，再還原至目標月份允許的日期，避免溢位。UTC 只作日曆運算載體。時、分保留，23 時子初換日仍由原引擎處理，不提前套在介面日期上。

這些結論來自原程式的直接重現與固定預期測試，不依賴星彧網站。有效輸入的核心計算完全未改：`engine.js` Git blob 仍為 `798e67fe08639ba1fb351b541502c92f06779d6b`。

## 日家、月家、年家新增待實盤確認項目

三種系統仍共用舊的按日近似年／月柱，陰盤及時家已改用實際交節時刻。以下是**目前程式的可重現差異**；右欄沿用同一輸入的 V14 陰盤／時家結果，沒有冒充本輪網站結果。

| 輸入 | 日家／月家／年家的年柱、月柱 | 陰盤／時家的年柱、月柱 |
|---|---|---|
| 2028-02-03 13:30 | 戊申、甲寅 | 丁未、癸丑 |
| 2028-02-04 15:00 | 戊申、甲寅 | 丁未、癸丑 |

| 2026-03-05 22:30 | 丙午、庚寅 | 丙午、辛卯 |

這不只是顯示文字的潛在影響：月家以月干支選旬首及轉盤，年家以年干支選旬首及轉盤。例如月家 2028-02-02 13:30 為陰三、甲辰旬、天任值符／生門值使；2028-02-03 13:30 已變為陰三、甲寅旬、天柱／驚門。必須核對網站該系統究竟按交節時分、整日或其他分界，才能決定年／月柱及盤面應否一起改，不能只改顯示造成新的矛盾。

日家目前依甲子日選最近冬夏至、以六十日循環起局；月家十個月一換局的公式、年家 180 年三元公式也尚無本輪網站盤圖支持。需要保留並比較完整盤面：陰陽遁、局數、旬首、值符值使、九星八門、天地盤與外圈天干。本輪未擅自把待確認的流派公式改成另一套。
