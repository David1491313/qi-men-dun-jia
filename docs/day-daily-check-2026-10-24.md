## 修正方式

1. 日家以子初換日後的日期，選最近一個「已到達」的冬夏至；不再用甲子日的距離挑選季節。
2. 冬夏至日期取鎖定版本lunar-javascript節氣表的當年夏至及`DONG_ZHI`，避免誤取前一年`冬至`；不使用近似日公式。
3. 依網站行為，日家在交節日整日換遁，23時進入該日即換盤；交節時分不參與日家轉遁。2025/6/20 22:59陽六、23:00陰三、6/21 00:00陰三；12/20 22:59陰一、23:00陽一、12/21 00:00陽一。2028兩個交界另有子初實盤。
4. 原有60日三元局數循環保留，改以正確季節基準計算；沒有加入單一日期或年份例外。
5. 修改僅限日家分支與其專用節氣快取；陰盤分時規則與時家置閏機械式錨點不共用此規則。

## 驗證與回歸

- `python scripts/audit-reference-headers.py --verify-sheets docs/day-daily-20261024/results.json`：76組保存的網站字形完全相符，可獨立重讀。
- `npm test`：72項通過。新增三組網站資料測試（52+12+12筆）與兩張代表盤的固定欄位測試。原有陰盤、時家、月家、年家與長生測試保留。
- 兩張代表盤核對旬首、符頭、值符值使、九星八門、天地盤主干／天芮寄干、八神、空亡、驛馬。網站日家盤未顯示外圈天干，外圈不列為已對照。
- 與V18比較：陰盤、時家、月家、年家各960組，共3,840組完整結果完全不變。範圍為2025–2028各月1/4/21/28，00/05/11/16/23時、30分。
- 同一日家960組中319組改變，均有陰陽遁／局數改變；另外641組完整輸出不變。319組屬程式比較，沒有宣稱319組已逐張網站驗證。日家完整快照有意由V16更新為V19，其餘三系統快照不變；外部網站預期值獨立保存，不能以快照代替。
- `npm run build`通過。`npm run audit:qimen`：103,390組結構檢查通過；這是自家檢查，不是網站對照。

## 尚未確認

未涵蓋1901–2100所有年份／每分鐘；目前只有指定日期的逐日與探查案例。1984冬至日期有兩組，其他歷史交節仍須補實盤。完整盤只核兩張代表盤，日家外圈未能從網站驗證。月家、年家本輪只有既有實盤測試及回歸，沒有新增逐日網站驗證。陰盤夏至其他年份仍待擴大對照。V18陰盤冬至成果及更正保留，未重新套用舊規則。
