## 修改規則及原因

舊版冬至當天固定12時轉陽，且冬至日期仍用21世紀近似係數。前者不能符合不同年份時分，後者在1984年會把12/22的冬至提前成12/21。

本輪以已核對樣本建立**指定網站的相容規則**，使用既有鎖版 `lunar-javascript 1.7.7` 表達，沒有硬編某一年的日期：

1. 冬至日期取當年的實際冬至日，使用節氣表 `DONG_ZHI`，不再用近似日公式。
2. 若當年冬至前已經過農曆閏月（閏月在1–10月），取當年冬至時分；其餘取前一年冬至時分。日期仍是當年冬至日。2033為閏十一月，冬至前尚未經過該閏月，所以走後者；已用15:55/15:56兩張盤確認。
3. 冬至當日23時子初換日後為陽遁；2025、2026兩年23:00均另實盤確認。冬至前一晚23時仍陰遁，保留V17已修正的原始民用日期判斷，不讓換日再次提前節氣。
4. 其餘冬至當日時間以輸入時分（秒為00）與上述時刻比較，分鐘參與重算。

關鍵例子：2027為普通年，網站04:50仍陰二、04:51已陽二，與前一年冬至04:50:14相符；2028閏五月，16:19陰八、16:20陽八，與當年冬至16:19:41相符；2029普通年也在16:19/16:20切換；2033閏十一月則在15:55/15:56切換。

這是依實盤建立的相容行為，不把它稱為所有陰盤流派的定義，也不把前一年時分冒稱當年天文冬至。未讀取網站隱藏程式，因此不推測網站內部為何採這種選擇。程式仍以通用農曆與節氣資料計算，不設年份特例表。

## 更正V16／V17的部分盤圖文字判讀

原盤檔沒有改動；錯誤在先前人工讀圖的文字紀錄：

- 2027-12-22 04:55 實際是**陽二**，不是陰二。因此先前「分界在04:55與04:56之間」的結論撤回；本輪重排確認為04:50陰二、04:51陽二。
- 2029-12-21 16:30 實際是**陽二**，不是陰一；22:00是**陽五**，不是陰五。

相關舊紀錄已附更正說明。這輪改用原圖固定字形的**RGB像素完全一致**比對，分開辨識陰／陽及一至九；遇到不認識或不唯一的字形即停止，不做近似OCR、不用引擎輸出補猜網站值。模板來源可在metadata逐項追溯。

可獨立從已保留拼圖重讀129個網站值：

```sh
python scripts/audit-reference-headers.py --verify-sheets docs/winter-daily-20261024/results.json
```

此工具只驗證參考圖讀值；`reference_ju`欄位來自網站像素，`engine_ju`及`engine_after_ju`分別記錄V17、V18，測試只拿`reference_ju`作固定預期值。
